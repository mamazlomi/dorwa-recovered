# دوروا — نسخه ۰.۱ (هسته)

داروخانه مجازی سراسری. این نسخه هسته سیستم است: دیتابیس، ورود، ثبت داروخانه، تایید توسط دوروا، موجودی، و صفحه عمومی هر داروخانه.

## استک
- **Next.js 15** (App Router، رابط فارسی راست‌به‌چپ)
- **Supabase** (PostgreSQL + احراز هویت + امنیت سطح ردیف)
- جستجوی مکانی با افزونه‌های `cube` و `earthdistance`

## ساختار
```
supabase/migrations/   تعریف دیتابیس (به ترتیب اجرا)
supabase/seed.sql      داروخانه‌های مجازی و محصولات نمونه — فقط محیط تست
supabase/tests/        آزمون‌های خودکار دیتابیس (۲۲ آزمون)
scripts/test-db.sh     اجرای آزمون‌ها روی Postgres محلی
src/app/               صفحات اپ
```

## صفحات
| مسیر | کاربرد |
| --- | --- |
| `/` | داروخانه‌های فعال هر شهر + «نزدیک‌ترین داروخانه به من» |
| `/<slug>` | صفحه عمومی داروخانه (مثلاً `/test-tehran-1`) |
| `/login` | ورود با لینک ایمیلی |
| `/pharmacy/register` | ثبت داروخانه (وضعیت «در انتظار تایید») |
| `/pharmacy/dashboard` | پنل داروخانه: وضعیت و موجودی |
| `/admin/pharmacies` | پنل دوروا: تایید یا رد داروخانه‌ها |

## قواعدی که دیتابیس خودش اجرا می‌کند (نه فقط رابط کاربری)
- داروخانه هیچ‌وقت داده داروخانه دیگر را نمی‌بیند یا تغییر نمی‌دهد.
- صاحب داروخانه نمی‌تواند خودش را تایید کند.
- تخفیف بیشتر از سقف دسته، قیمت بیشتر از سقف دوروا، و هر تخفیفی روی داروی نسخه‌ای رد می‌شود.
- مشتری موجودی دقیق را نمی‌بیند؛ فقط «موجود» و قیمت نهایی.
- همه ستینگ‌ها (شعاع، مهلت‌ها، کمیسیون) بدون کدنویسی قابل تغییرند و هر تغییر ثبت می‌شود.

## اجرا (برای برنامه‌نویس)
```bash
cp .env.example .env.local   # مقادیر پروژه Supabase دوروا
npm install
npm run dev
npm run test:db              # نیاز به PostgreSQL 16 محلی
```

## اولین مدیر دوروا
پس از اولین ورود، این دستور را در SQL Editor پروژه اجرا کنید (ایمیل خودتان):
```sql
insert into memberships (user_id, pharmacy_id, role_id)
select u.id, null, r.id from auth.users u, roles r
where u.email = 'YOUR@EMAIL' and r.scope = 'platform' and r.code = 'super_admin';
```

## هنوز ساخته نشده (فاز بعد)
سبد خرید و تخصیص سبد، پرداخت امانی، نسخه، تایید فنی، پرونده مشتری، ورود با پیامک، همگام‌سازی با کاتالوگ.

## دور ۷ (افزوده‌شده)
**ورود با پیامک** — مایگریشن `053`، `src/lib/phoneAuth.ts`، `src/lib/sms.ts`، بخش «ورود با پیامک» در `/login`.
- کد ۵ رقمی، ۲ دقیقه اعتبار، ۵ تلاش، ۱ کد در دقیقه، ۵ کد در ساعت برای هر شماره و ۲۰ کد در ساعت برای هر IP.
- کد فقط به‌صورت HMAC ذخیره می‌شود و جدول `phone_otps` برای مرورگر بسته است.
- حساب با ایمیل ساختگی `p9XXXXXXXXX@phone.dorva.ir` ساخته می‌شود (نه با `profiles.mobile` که کاربر آزادانه می‌نویسد).
- متغیرهای لازم روی Vercel: `SUPABASE_SERVICE_ROLE_KEY`، `SMS_API_KEY`، `SMS_SENDER` (نمونه در `.env.example`).

**مشاوره، فروم علمی و مجله** — مایگریشن `054`، صفحه‌های `/forum`، `/forum/[id]`، `/forum/consultant`، `/magazine`، پنل `/admin/consult` (مجوز `consult.manage`).
- فقط مشاور تاییدشده پاسخ می‌دهد؛ مشاور خودش را تایید نمی‌کند.
- نشان «تایید دوروا» را فقط کارکنان دوروا می‌گذارند.
- پرسش خصوصی فقط برای پرسنده، مشاوران و کارکنان دیده می‌شود. نام پرسنده هیچ‌جا نمایش داده نمی‌شود.
- آزمون‌ها: `supabase/tests/115_consult_tests.sql`.

**فروم سلامت (جدا از مشاوره)** — مایگریشن `055`، صفحه‌های `/forum`، `/forum/[id]`، `/forum/review`. مشاوره به `/consult` منتقل شد.
- هر کاربر واردشده می‌تواند گفتگو یا نظر بگذارد (۳۰ در روز). همه‌ی نظرها «در انتظار بررسی» شروع می‌شوند.
- مشاور تاییدشده یا کارمند دوروا: تایید، ثبت توضیح، یا «نیاز به بررسی ندارد». متن نظر هیچ‌وقت قابل ویرایش نیست. مخفی‌کردن فقط با کارمند.

**گردش کار متخصصان، امتیاز و پرداخت** — مایگریشن `056`.
- متخصص نظر را از صف «برمی‌دارد» (قفل N دقیقه‌ای)، نتیجه را ثبت می‌کند و نامش با تخصص کنار تایید دیده می‌شود.
- هر بررسی/پاسخ مشاوره یک «اعتبار» (امتیاز + دقیقه) می‌سازد؛ پرداخت بر اساس امتیاز یا ساعت کار از تنظیمات.
- `/admin/reviewers`: مانده‌ی هر متخصص و ثبت پرداخت (مجوز `consult.payout`). سیستم پولی جابه‌جا نمی‌کند، فقط ثبت می‌کند.
- همه‌ی سقف‌ها و نرخ‌ها در «تنظیمات › فروم و متخصصان». تنظیمات و منوی ادمین دسته‌بندی شدند.
- برای اجرای یک‌جا: `supabase/run_once/round7_all.sql` (۰۵۳ تا ۰۵۶).

**صلاحیت و نظارت بر متخصصان** — مایگریشن `057`، صفحه‌ی `/admin/experts`.
- عضویت (مشتری/کارمند) صلاحیت نمی‌دهد. داروساز تاییدشده (مسئول فنی فعال با شماره‌ی نظام) همان لحظه‌ی درخواست پذیرفته می‌شود و پس از آن همیشه صلاحیت دارد؛ بقیه را دوروا با ثبت «مبنای تایید» می‌پذیرد.
- هر تغییر وضعیت (پذیرش، رد، هشدار، توقف موقت، تعلیق، بازگرداندن، حذف) فقط از `reviewer_set_status` می‌گذرد، دلیل می‌خواهد و در `reviewer_events` ثبت می‌شود. متخصص وضعیت و بازخورد را در `/forum/review` می‌بیند.
- تاخیر (پایان مهلت بدون نتیجه) و بازبینی نادرست (حسابرسی نمونه‌ای) امتیاز منفی است؛ عبور از سقف‌ها در بازه‌ی تنظیم‌شده به توقف خودکار می‌انجامد. همه‌ی عددها در تنظیمات › فروم و متخصصان.

# دوروا — نسخه ۰.۱ (هسته)

داروخانه مجازی سراسری. این نسخه هسته سیستم است: دیتابیس، ورود، ثبت داروخانه، تایید توسط دوروا، موجودی، و صفحه عمومی هر داروخانه.

## استک
- **Next.js 15** (App Router، رابط فارسی راست‌به‌چپ)
- **Supabase** (PostgreSQL + احراز هویت + امنیت سطح ردیف)
- جستجوی مکانی با افزونه‌های `cube` و `earthdistance`

## ساختار
```
supabase/migrations/   تعریف دیتابیس (به ترتیب اجرا)
supabase/seed.sql      داروخانه‌های مجازی و محصولات نمونه — فقط محیط تست
supabase/tests/        آزمون‌های خودکار دیتابیس (۲۲ آزمون)
scripts/test-db.sh     اجرای آزمون‌ها روی Postgres محلی
src/app/               صفحات اپ
```

## صفحات
| مسیر | کاربرد |
| --- | --- |
| `/` | داروخانه‌های فعال هر شهر + «نزدیک‌ترین داروخانه به من» |
| `/<slug>` | صفحه عمومی داروخانه (مثلاً `/test-tehran-1`) |
| `/login` | ورود با لینک ایمیلی |
| `/pharmacy/register` | ثبت داروخانه (وضعیت «در انتظار تایید») |
| `/pharmacy/dashboard` | پنل داروخانه: وضعیت و موجودی |
| `/admin/pharmacies` | پنل دوروا: تایید یا رد داروخانه‌ها |

## قواعدی که دیتابیس خودش اجرا می‌کند (نه فقط رابط کاربری)
- داروخانه هیچ‌وقت داده داروخانه دیگر را نمی‌بیند یا تغییر نمی‌دهد.
- صاحب داروخانه نمی‌تواند خودش را تایید کند.
- تخفیف بیشتر از سقف دسته، قیمت بیشتر از سقف دوروا، و هر تخفیفی روی داروی نسخه‌ای رد می‌شود.
- مشتری موجودی دقیق را نمی‌بیند؛ فقط «موجود» و قیمت نهایی.
- همه ستینگ‌ها (شعاع، مهلت‌ها، کمیسیون) بدون کدنویسی قابل تغییرند و هر تغییر ثبت می‌شود.

## اجرا (برای برنامه‌نویس)
```bash
cp .env.example .env.local   # مقادیر پروژه Supabase دوروا
npm install
npm run dev
npm run test:db              # نیاز به PostgreSQL 16 محلی
```

## اولین مدیر دوروا
پس از اولین ورود، این دستور را در SQL Editor پروژه اجرا کنید (ایمیل خودتان):
```sql
insert into memberships (user_id, pharmacy_id, role_id)
select u.id, null, r.id from auth.users u, roles r
where u.email = 'YOUR@EMAIL' and r.scope = 'platform' and r.code = 'super_admin';
```
